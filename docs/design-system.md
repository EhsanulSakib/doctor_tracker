# Doctor Tracker design system

The rules and values behind every screen of the admin portal. Colours, type, spacing, radii, elevation, motion and component states all come from tokens defined in one stylesheet. Components never use raw values, so a theme or brand change happens in one place.

| What | Where |
|---|---|
| Tokens (all three layers) | [`frontend/src/app/globals.css`](../frontend/src/app/globals.css) |
| Token names `cn()` must know when merging classes | [`frontend/src/lib/utils.ts`](../frontend/src/lib/utils.ts) |
| Motion presets | [`frontend/src/lib/motion.ts`](../frontend/src/lib/motion.ts) |
| Breakpoints for JavaScript | [`frontend/src/lib/breakpoints.ts`](../frontend/src/lib/breakpoints.ts) |
| UI components | [`frontend/src/components/ui/`](../frontend/src/components/ui/) |

## 1. Token layers

```
Primitive        --indigo-600: #4f46e5          raw palette, never used by components
    ↓
Semantic         --accent: var(--indigo-600)     what a colour is for; dark theme re-points it
    ↓
Component        --chart-accent: var(--accent)…  one part of the UI
    ↓
Utility          bg-accent, text-ink-muted…      what components write (generated by @theme inline)
```

- **Primitives** are named by hue and step (`--slate-500`, `--red-700`). Most match Tailwind's palette. A few custom steps fill gaps Tailwind doesn't have: `--slate-850`, `--slate-925`, and the `-960` / `-990` tints used for soft fills on dark surfaces.
- **Semantic** tokens say what a value is for (`--paper`, `--ink`, `--danger-soft`). The light theme sets them in `:root`. `[data-theme="dark"]` points the same names at other primitives, so components never need a `dark:` class for colour.
- **Component** tokens belong to one part of the UI: chart fills, the login photo scrim, the focus ring, the scrollbar thumb, the table header rule. Change one and only that component changes.
- **Utilities** are what the code uses. `@theme inline` turns each semantic and component colour into Tailwind utilities (`bg-*`, `text-*`, `border-*`, `ring-*`, `fill-*`…).

### Rules

1. **Colours come from tokens only.** Tailwind's own palette is switched off (`--color-*: initial`), so `bg-red-500` or `text-white` generates no CSS at all. Hex values in components are not allowed.
2. **No arbitrary values for things the scale already has.** Use `text-ui`, not `text-[13px]`. Use `h-5.5` (22px, on the 4px spacing scale), not `h-[22px]`. Use `rounded-tag`, not `rounded-[6px]`. The allowed exceptions are in [section 11](#11-allowed-arbitrary-values).
3. **Pick the semantic name, not the look.** Use `text-accent-fg` for accent text and `bg-accent` for an accent fill. The two differ in dark mode: indigo-300 text, indigo-600 fill.
4. **A new token goes into `cn()`'s list too** (`lib/utils.ts`). Otherwise `cn("text-ui", "text-ink")` treats both as colours and drops one.

### Measured contrast (WCAG AA needs 4.5:1 for text)

| Text on background | Light | Dark |
|---|---|---|
| `ink` on `paper` / `surface` | 17.1 / 17.9 | 17.3 / 16.2 |
| `ink-muted` on `surface` | 4.8 | 6.9 |
| `accent-ink` on `accent` | 6.3 | 6.3 |
| `accent-fg` on `surface` / `accent-soft` | 6.3 / 5.6 | 8.9 / 8.0 |
| `danger-ink` on `danger` | 6.5 | 6.9 |
| `danger` on `surface` / `danger-soft` | 6.5 / 5.9 | 6.4 / 5.9 |
| `warning` on `warning-soft` | 4.8 | 8.3 |
| `success` on `success-soft` | 5.2 | 7.6 |
| `info` on `info-soft` | 5.6 | 9.5 |

`ink-muted` on `paper-2` is only 4.3:1 in light. That's why muted text turns `ink` when its row or button gets the `paper-2` hover fill (ghost buttons, nav items, menu rows already do this).

The chart palette was checked with a palette validator: lightness band, colour-blind separation, and 3:1 against the card surface. Each status block also carries a text label, and the legend repeats it, so colour is never the only signal.

The browser chrome colour (`themeColor` in `app/layout.tsx`) repeats `--paper` as literal hex, because a meta tag can't read CSS variables. Change both together.

## 3. Typography

**Plus Jakarta Sans** for everything (`font-sans`); **JetBrains Mono** (`font-mono`) where digits must line up in code-like strings. Figures in tables, the clock and KPIs use `tabular-nums`. Body text is 14px with line height 1.5 on `ink`.

| Utility | Size | Line height | Use |
|---|---|---|---|
| `text-micro` | 10px | context | count inside the notification bubble |
| `text-caption` | 11px | context | chart axis ticks, timestamps, weekday headers, role tag |
| `text-label` | 11px | 16px, tracking 0.07em, uppercase | section labels, table headers |
| `text-xs` (Tailwind) | 12px | 16px | second line of a cell, badges, helper text |
| `text-ui` | 13px | context | dense UI: breadcrumb, menus, small buttons, table cards, calendar |
| `text-sm` (Tailwind) | 14px | 20px | body, inputs from `sm`, medium buttons |
| `text-lead` | 15px | context | wordmark, phone page title, empty-state heading, large buttons, phone nav |
| `text-base` (Tailwind) | 16px | 24px | inputs on phones (smaller makes iOS zoom in on focus) |
| `text-title` | 22px | 30px, tracking −0.02em | dialog and section titles |
| `text-figure` | 26px | context | the big time in the clock panel |

"Context" means the size token sets only `font-size`. Line height comes from the parent (body: 1.5) or from a `leading-*` class next to it. That keeps each text box exactly as tall as the design measured (e.g. `text-ui leading-4.5`).

Weights: 400 body, 500 labels and buttons, 600 headings, names and selected states, 700 only for the notification count.

## 4. Spacing and sizing

Tailwind's 4px scale (`--spacing: 0.25rem`) is the only spacing scale. Quarter steps are allowed where a measured height needs them: `0.75` = 3px, `4.5` = 18px, `5.5` = 22px, `29.5` = 118px.

| Pattern | Value |
|---|---|
| Page padding | `px-4 py-5` on phones, `sm:px-6`, `lg:py-6` |
| Gap between page blocks | `gap-3` (lists), `gap-4` (dashboard grid) |
| Card padding | `p-4`, `sm:p-5` |
| Control height (mouse / touch) | small 32 / 40px (`h-8 pointer-coarse:h-10`); medium 36 / 44px (`h-9 pointer-coarse:h-11`); large 44px |
| Icon button | 32 / 40px (`sm`), 36 / 44px (`md`) |
| Table cell | `px-4 py-3` |

Layout tokens (component layer, in `@theme`):

| Utility | Value | Use |
|---|---|---|
| `w-sidebar` / `pl-sidebar` | 15rem (240px) | expanded sidebar, and the shell's matching left padding |
| `w-sidebar-rail` / `pl-sidebar-rail` | 4rem (64px) | icon rail on tablets and when collapsed |
| `h-topbar` | 3.5rem (56px) | top bar, sidebar logo row and phone drawer header (they line up) |
| `max-w-popover` | `100vw − 1rem` | floating panels keep 8px from each screen edge |
| `@kpi:` (container query) | tile ≥ 13.75rem | a stat tile wide enough for its longest label and value puts the value on the right |

On laptops and up (≥ 1024px) the shell is exactly one viewport tall. Only `<main>` or a table body scrolls, so the window never shows a scrollbar.

## 6. Elevation and layers

| Utility | Use |
|---|---|
| `shadow-card` | cards, tables, secondary buttons, selected calendar day |
| `shadow-overlay` | dialogs, popovers, dropdowns, toasts |
| `shadow-table-head` | sticky table header rule |

Dark mode uses deeper black shadows, because slate shadows vanish on dark surfaces. Stacking order, low to high:
1. sticky table header `z-10`
2. top bar `z-20`
3. sidebar `z-30`
4. dialog / drawer `z-50`
5. popovers and dropdowns `z-60` (they open from inside dialogs)
6. toasts `z-70`
7. skip link `z-80`

## 7. Motion

| Preset (`lib/motion.ts`) | Feel | Used by |
|---|---|---|
| `transitions.fast` / `base` / `slow` | 150 / 200 / 250ms, ease-out `(0.2, 0.8, 0.2, 1)` | colour and position changes |
| `transitions.exit` | 120ms ease-in | anything leaving (exits are faster than entrances) |
| `popIn` | snappy spring, scale 0.96 → 1 + fade | dialogs on tablet and desktop |
| `sheetUp` | spring from the bottom edge | dialogs on phones (bottom sheet with a grab handle) |
| `menuPanel` / `menuItem` | panel scales from its anchor, items stagger in | Select, account menu, notifications |
| `highlightSpring` | stiff spring | the single highlight that glides between options; nav `layoutId` |
| `listStagger` / `listItem` | 20ms stagger | dashboard tiles and lists |

CSS keyframes (in `@theme`): `animate-rise`, `animate-grow-x`, `animate-reveal-x`, `animate-fade-in`, `animate-ping-slow` and `animate-bell-ring`. All motion animates `transform`, `opacity` or `clip-path` only, so it never shifts layout. With "reduce motion" on, `MotionConfig reducedMotion="user"` drops transforms and the global rule in `globals.css` cuts CSS animations to 0.01ms.

The easing is also a utility: `ease-clinical`.

## 8. Breakpoints and touch

Tailwind's defaults: `sm` 640px, `md` 768px, `lg` 1024px, `xl` 1280px. CSS uses the variants. JavaScript uses `below("sm")` / `atLeast("xl")` from `lib/breakpoints.ts`, never a hand-typed media query.

| Width | Layout |
|---|---|
| < 640px | phone: drawer navigation, dialogs become bottom sheets, list rows become cards |
| 640–1023px | tablet: icon-rail sidebar; wide tables (`cardsBelow="lg"`) show two-column cards |
| ≥ 1024px | laptop: full sidebar (collapsible), one-viewport shell, tables |

`pointer-coarse:` raises every target to at least 40px on touch screens. A small text link keeps its size and gets a stretched `::after` tap area. Tap areas of neighbouring links never overlap.

## 9. Component states

Every interactive element shows keyboard focus with the `focus-ring` utility: a 2px `--focus-ring` outline, offset 2px, on `:focus-visible` only. Fields are the exception: they show focus with an accent border and a soft ring. Disabled controls go to 50% opacity and ignore the pointer.

**Button** (`variant`: primary, secondary, ghost, danger)

| | Default | Hover | Pressed | Disabled | Loading |
|---|---|---|---|---|---|
| primary | `bg-accent` `text-accent-ink`, soft accent shadow | `bg-accent-hover` | scale 0.98 | 50% opacity | spinner replaces the icon, label stays (no width jump), `aria-busy` |
| secondary | `bg-surface` `border-line` `text-ink` `shadow-card` | `border-line-strong` `bg-paper-2` | scale 0.98 | 50% | same |
| ghost | `text-ink-muted` | `bg-paper-2` `text-ink` | scale 0.98 | 50% | same |
| danger | `bg-danger` `text-danger-ink` | `bg-danger-hover` | scale 0.98 | 50% | same |

**IconButton**: always circular, with a required `label` (used for `aria-label` and the tooltip). Ghost: `text-ink-muted` → hover `bg-paper-2 text-ink`. Secondary adds a border and `shadow-card`. A destructive icon turns `text-danger` on hover.

**Fields** (Input, Textarea, Select trigger, DatePicker, DateRangeField, SuggestInput, DoctorSelect)

| Default | Hover | Focus | Invalid | Disabled |
|---|---|---|---|---|
| `border-line-strong` `bg-surface`, placeholder `ink-subtle` | `border-ink-subtle` | `border-accent` + 3px `accent/20` ring | `border-danger` (+ `danger/20` ring on focus), driven by `aria-invalid`; the message sits under the field | `bg-paper-2` `text-ink-subtle` |

**Options** (Select, comboboxes, menus): one `paper-2` highlight glides to the hovered or arrowed option. The selected option gets an `accent-fg` checkmark that pops in. The "All …" option is muted and separated by a hairline.

**Navigation item**: idle `text-ink-muted`; hover `bg-paper-2 text-ink`; current page `text-accent-fg` on an `accent-soft` highlight that slides between items, plus `aria-current="page"`.

**Calendar day and pagination page**: idle `text-ink`; hover `bg-paper-2`; selected or current `bg-accent text-accent-ink`. A range gets an `accent-soft` band between its ends. Today has a small `accent-fg` dot, and days outside the allowed range are muted and inactive.

**Badge** (`tone`): `neutral`, `accent`, `success`, `warning`, `danger`, `info`. Each is a `*-soft` fill, `*` text and an inset ring at 15–20%. Status badges add a leading dot, and the text always names the status.

**Table row**: hover `bg-paper/80`. Row actions are icon buttons. Below the `cardsBelow` breakpoint each row becomes a card, and its edit and delete buttons stay visible.

**Toast**: a `surface` panel with `shadow-overlay` and a tone icon (success, info, error). It stays 4s / 5s / 8s and pauses while hovered or focused. Errors are announced assertively, the others politely.

**Stat tile** (dashboard KPIs):
- Wide tiles (`@kpi`) put the label (`text-xs`, `ink-muted`) and the context line on the left, and the value (`text-2xl` semibold) on the right, vertically centred. Narrow tiles stack label, value and context.
- The value counts up on arrival and on a range switch, with no layout shift (see the FE guide).
- A change in the context line uses `success` or `danger` with an arrow, and its text always says the direction.

**Loading**: `Skeleton` bars (`bg-line/70`, pulse) cut to the exact size of the content they stand for, so nothing moves when data arrives.

**Empty**: `EmptyState` shows an icon in a circle, a `text-lead` heading and one action. No filler text.

## 10. Adding or changing a token

1. Need a new raw colour? Add the primitive to the first `:root` block in `globals.css`.
2. Add or re-point the semantic token in the light `:root` block, and in `[data-theme="dark"]` if it differs.
3. Expose it as a utility: `--color-<name>: var(--<name>)` in `@theme inline`. Type, radius and layout sizes go in the plain `@theme` block.
4. Add the name to the matching list in `lib/utils.ts` (`color`, `text`, `radius`, `shadow`, `spacing`, `container`).
5. Check text contrast in both themes (≥ 4.5:1) and add a row to this document.

## 11. Allowed arbitrary values

These stay as arbitrary values because no scale step expresses them:

- `transition-[…]` property lists
- `pb-[max(1rem,env(safe-area-inset-bottom))]` (phone safe area)
- `max-h-[92dvh]` (dialog)
- `w-[min(18rem,85vw)]` (phone drawer)
- `max-h-[min(var(--panel-max-height,18rem),18rem)]` (dropdowns shrink to the space left on screen)
- grid templates: `grid-cols-[1fr_auto]`, `grid-rows-[minmax(0,4fr)_minmax(0,6fr)]`, `grid-cols-[300px_1fr]` (clock panel)
- `basis-[calc(100%-4.5rem)]`
- `object-[35%_30%]` (focal point of the login photo)
- `h-[calc(var(--text-lead)*1.5)]` (a skeleton the height of one `text-lead` line)

To find anything else that crept in, run from `frontend/src`:

```bash
grep -rhoE "[a-z:-]*-\[[^]]+\]" --include=*.tsx . | sed -E 's/^([a-z-]+:)*//' | sort | uniq -c | sort -rn
```
